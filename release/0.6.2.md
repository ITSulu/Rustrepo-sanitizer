# Rustrepo-sanitizer 0.6.2

Rustrepo-sanitizer 0.6.2 completes the size-unit and interface-parity work that
began in 0.6.1. All three interfaces now accept and display binary units from a
single shared model, repository sources behave the same wherever they are
offered, and the web interface has full browser coverage.

## Binary size units

`src/size.rs` provides one typed parser, converter, and formatter. A value
entered as `10 MiB` means exactly the same number of bytes in the CLI, the
desktop GUI, and the web UI.

- **CLI**: `--max-file-size` accepts plain bytes or `KiB`/`MiB`/`GiB`, defaults
  to `10MiB`, rejects unknown units with a readable message, documents the
  syntax in `--help`, and reports the effective limit with a unit:

  ```
  sanitized 2 files (0 excluded, 0 redactions, max file size 2 MiB); dry run
  ```

- **GUI**: Advanced Options carries a numeric field with a KiB/MiB/GiB
  selector. Changing the unit preserves the exact byte count; the conversion
  runs in Rust rather than in Slint, so a rounded display value can never alter
  the size that is applied.

- **Web**: Output carries the same field and selector, and the form submits the
  byte-equivalent value. Without scripting the server still resolves the value
  and its unit with the shared parser, so the field works either way.

A client-supplied size is clamped server side, so a crafted request can neither
disable the size filter nor exclude every file.

## Interface parity

- The **Branch Or Tag** field now reaches git for plain Git URLs. Previously the
  field was offered for every source but dropped for a URL, so a requested ref
  was silently replaced by the default branch.
- The **desktop GUI** offers Local Path, Git URL, GitHub Repository, and Forgejo
  Repository with a branch field. Remote sources have no server, token, or
  network policy in the desktop app, so they are refused with a clear message
  instead of quietly sanitizing the local path.
- **Common glob presets** live in one registry emitted by the build script, so
  the GUI and web filter dropdowns cannot drift apart.

## Web interface

- Headings and field labels use title case.
- Dropdown options stay readable in both the light and dark themes.
- Supported Formats moved into Output, below Maximum File Size.
- The repository source block places Forgejo Repository on its own line below
  Server Local Path, with Branch Or Tag beside the repository fields.
- Top navigation moves between Sanitize and Option Reference.
- Option-reference fields show a one-line tooltip after a two second hover, and
  the help text is wide enough to stay on one line.
- Include and Exclude globs have working lists: a common-pattern dropdown, an
  Add button, a custom pattern field, and a Remove control per entry. The
  applied patterns are submitted as the values the server already parses.
- Repository, path, and tag fields use non-email input semantics and disable
  autofill, so browsers stop offering email aliases.

## Accessibility

- Status banners keep their style class, which Leptos previously dropped when
  merging a static and a dynamic class.
- The custom pattern fields have labels, and the two Add buttons have distinct
  accessible names.
- Dark theme button fills and card borders meet the 3:1 non-text contrast
  minimum.
- Desktop text inputs use a light grey, and the fields regain the background,
  border, focus ring, and placeholder that a theming change had dropped.

## Testing

- 226 Rust tests, including behavioural coverage of the CLI size argument, the
  GUI unit selector and source guard, the web size clamp, and glob merging.
- 23 Playwright browser tests covering navigation, tooltips, unit conversion,
  filter lists, downloads, validation, accessibility, and real acquisition from
  a public repository. The suite runs in Forgejo CI on the primary runner and
  creates its fixtures with `mktemp`.
- The native AT-SPI GUI accessibility harness passes.
- `cargo fmt --check`, `cargo clippy --all-targets --all-features -D warnings`,
  and `cargo audit` are clean.
