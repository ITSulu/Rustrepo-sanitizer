# Rustrepo-sanitizer 0.6.0

## Summary

Rustrepo-sanitizer 0.6.0 adds a self-hosted web frontend: an Axum HTTP/API
server and a Leptos server-rendered UI at feature parity with the CLI and the
desktop GUI. All three frontends call the same sanitizer core, so there is one
implementation of acquisition-agnostic sanitization. The web server is
stateless apart from bounded, expiring job workspaces and the configured
Forgejo/GitHub integrations.

## Features

- Five repository input modes: server-local path (restricted to configured
  roots), public https Git URL, uploaded zip/tar archive, and Forgejo/GitHub
  repository selectors that clone server-side.
- Feature parity with the CLI and GUI: output naming, archive/compression,
  include/exclude globs, include-untracked, redaction and fail-on-secret,
  reports, ZIP AES passwords with policy, and advanced options.
- Browser downloads for the sanitized archive and its embedded reports
  (`SANITIZATION-REPORT`, `REPOSITORY-INVENTORY`, `SECRET-AUDIT`, `manifest`).
- Accessible, responsive server-rendered UI: semantic controls with labels and
  help text, keyboard navigation without JavaScript, visible focus, and
  announced status/errors.
- Token-protected JSON API for automation (`Authorization: Bearer`), separate
  from the human-facing UI.

## Security

- Repository URLs are restricted to https, reject embedded credentials and
  private/loopback/reserved addresses (including DNS-resolved and IPv4-mapped
  addresses), and disable the `ext`/`file` Git transports.
- Uploads are streamed under a size bound; archives are extracted with
  traversal, symlink, entry-count, and byte-budget checks.
- Output names, workspace paths, and Git refs are validated to prevent
  directory traversal and option injection.
- Forgejo/GitHub tokens are read from the server environment only, never
  serialized into a response, and never exposed to the browser.
- Jobs run in isolated temp workspaces that are removed on completion, expiry,
  or startup cleanup; concurrency is bounded.
